Getting Started

What is a DeathClient JavaScript plugin?

A DeathClient plugin is simply a .js file that runs inside DeathClient's built-in JavaScript environment.

You do not need to know Java, TeaVM, Minecraft modding, or OpenGL to make a basic plugin. You can start by copying one of the examples below and changing the names, messages, settings, and actions.

Built-in editor: DeathClient includes a VS Code-style JavaScript editor. Open the JavaScript Plugins menu, create or edit a plugin, then save it. The editor supports syntax highlighting, themes, file loading, and hot-loading.

Your first plugin

Copy this entire script into a new JavaScript plugin: 

const dc = window.DeathClient;

dc.createMod({
    name: "Hello World",
    description: "My first DeathClient plugin",
    category: "PLAYER",
    isCheat: false,

    onEnable: function() {
        dc.chat("§aHello from my plugin!");
    },

    onUpdate: function() {
        // This runs every game tick.
    }
});

The important parts are:

1
Get the API.
const dc = window.DeathClient;
2
Create a mod.
dc.createMod({...})
3
Give it behavior.
Use callbacks such as onEnable, onUpdate, and onChat.
4
Use the API.
For example: dc.chat(), dc.sendCommand(), dc.player.jump(), and dc.storage.set().

JavaScript Basics

You only need a small amount of JavaScript to make useful DeathClient plugins. These are the fundamentals you will use most often.

Variables

A variable stores information. 

let price = 10;
let playerName = "Steve";
let enabled = true;
Example What it means
let x = 10; Create a variable named x containing 10.
let name = "Steve"; Create a text value.
let enabled = true; Create a true/false value.

Changing variables

let price = 10;

price = 20;
price += 5;
price -= 2;

After these operations, price is 23.

Conditions

if (dc.player.health < 5) {
    dc.chat("§cLow health!");
}

Functions

function sayHello(name) {
    dc.chat("Hello " + name);
}

sayHello("Steve");

Repeating logic

A DeathClient onUpdate callback runs approximately once per client tick. 

onUpdate: function() {
    if (dc.player.onGround) {
        dc.player.jump();
    }
}

Useful operators

Operator Example Meaning
=== x === 10 Exactly equal.
!== x !== 10 Not equal.
> x > 10 Greater than.
< x < 10 Less than.
&& a && b Both conditions must be true.
|| a || b At least one condition is true.
! !enabled Invert true/false.

Plugin Structure

You can make one plugin file contain multiple mods, HUDs, commands, event handlers, settings, timers, and storage systems.

A common structure is:

const dc = window.DeathClient;

// Settings / constants
const PRICE = 10;

// Main mod
dc.createMod({
    name: "Example",
    description: "Example plugin",
    category: "PLAYER",
    settings: [],
    onEnable: function() {},
    onDisable: function() {},
    onUpdate: function(settings) {},
    onChat: function(message) {}
});

// Global events
dc.on("chat_receive", function(data) {
});

// Custom command
dc.createCommand({
    command: "example",
    prefix: ".",
    execute: function(args) {
    }
});
Tip: You do not have to use every system. Start with a mod and an onUpdate callback, then add APIs as you need them.

Beginner Recipes

These are copy-and-modify examples for people who do not know much JavaScript yet.

Say something when the mod is enabled

dc.createMod({
    name: "Welcome",
    description: "Sends a message when enabled",
    category: "PLAYER",

    onEnable: function() {
        dc.chat("§aWelcome!");
    }
});

Send a server command

dc.sendCommand("spawn");

You can also write: 

dc.sendCommand("/spawn");

Both become a slash command.

Display a title

dc.showTitle(
    "§cWARNING",
    "§7Something happened!"
);

Play a sound

dc.playSound(
    "random.orb",
    1.0,
    1.0
);

React to chat

dc.on("chat_receive", function(data) {

    if (data.message.indexOf("joined") !== -1) {
        dc.chat("§aSomeone joined!");
    }

});

Automatically jump

dc.createMod({
    name: "Auto Jump",
    description: "Automatically jumps while enabled",
    category: "MOVEMENT",
    isCheat: true,

    onUpdate: function() {
        if (dc.player.onGround) {
            dc.player.jump();
        }
    }
});

Run something every second

let timer = 0;

dc.createMod({
    name: "Timer Example",

    onUpdate: function() {

        timer++;

        if (timer >= 20) {
            timer = 0;

            dc.chat("§eOne second passed.");
        }
    }
});

There are 20 normal Minecraft client ticks per second, so this is a useful simple timer technique.

Mod Registration

Register a normal module with dc.createMod(config).

Property Type Description
name String Required. Exact module name.
displayName String Optional GUI display name. Defaults to name.
description String Description shown in the ClickGUI.
category String MOVEMENT, COMBAT, RENDER, WORLD, PLAYER, or HUD.

Commands API

Register a local JavaScript command with dc.createCommand(). These commands are handled by DeathClient instead of being sent to the server as normal chat. 

dc.createCommand({

    command: "hello",

    prefix: ".",

    description: "Says hello",

    execute: function(args) {

        dc.chat(
            "§aHello!"
        );

        dc.chat(
            "Arguments: " + args
        );
    }
});

Typing: 

.hello test something

gives: 

args = "test something"

Command with arguments

dc.createCommand({

    command: "say",

    prefix: ".",

    execute: function(args) {

        if (!args || !args.trim()) {
            dc.chat("§cUsage: .say <message>");
            return;
        }

        dc.chat(
            "§aYou said: §f" + args
        );
    }
});

Command with multiple arguments

dc.createCommand({

    command: "teleport",

    prefix: ".",

    execute: function(args) {

        let parts =
            String(args)
                .trim()
                .split(/\s+/);

        let x = Number(parts[0]);
        let y = Number(parts[1]);
        let z = Number(parts[2]);

        dc.player.x = x;
        dc.player.y = y;
        dc.player.z = z;
    }
});

Mod Callbacks

Callback When it runs
onEnable(settings) When the module is enabled.
onDisable(settings) When the module is disabled.
onUpdate(settings) Every client tick.
onRender2D(settings) Every render frame.
onChat(message) When a chat message is delivered to the module.
Performance: onUpdate can run many times over the lifetime of a plugin. Avoid expensive loops, huge allocations, repeated downloads, or large JSON operations every tick.

dc.createHudMod({

    name: "My HUD",

    description: "A custom HUD element",

    category: "HUD",

    width: 100,

    height: 20,

    onRender2D: function() {

        /*
         * this.x
         * this.y
         * this.scale
         *
         * are synchronized with the Java HUD system.
         */

    }

});

HUD properties

Property Description
this.x Current X position.
this.y Current Y position.
this.scale Current scale multiplier.
The current bridge synchronizes HUD position and scale with Java. Rendering helpers such as dc.drawString() are not part of the current bridge shown in this documentation unless a future bridge version adds them.

Event System

Global events let plugins listen for activity without putting all logic inside one mod.

Registering an event

dc.on("chat_receive", function(data) {

    dc.chat(
        "Received: " + data.message
    );

});

Removing an event

function handleChat(data) {
    dc.chat(data.message);
}

dc.on("chat_receive", handleChat);

dc.off("chat_receive", handleChat);

Run once

dc.once("chat_receive", function(data) {
    dc.chat("This only runs once.");
});

Available events

Event Payload Description
tick Player state object Fires every client tick.
chat_receive { message } Incoming chat delivered by the client.
mod_enable { name } A module was enabled.
mod_disable { name } A module was disabled.
resource_loaded { id, url, data } A resource fetch completed.
resource_error { id, url, error } A resource fetch failed.
resource_imported { name, type, size } A local resource was imported.

Data Persistence

Plugin storage lets you save values across page reloads and client restarts using browser local storage.

Save a value

dc.storage.set(
    "coins",
    250
);

Objects and arrays can also be stored: 

dc.storage.set(
    "settings",
    {
        price: 10,
        enabled: true
    }
);

Load a value

let coins =
    dc.storage.get("coins", 0);

dc.chat(
    "Coins: " + coins
);

Delete a value

dc.storage.remove("coins");

Clear plugin storage

dc.storage.clear("compete_");

This is useful for grouping your plugin's values: 

dc.storage.set(
    "compete_bans",
    ["Steve", "Alex"]
);

dc.storage.set(
    "compete_price",
    10
);

Legacy string-file API

The older file helpers are still available:

API Description
dc.saveFile(key, value) Saves a string value.
dc.loadFile(key) Loads a string value or returns null.
dc.deleteFile(key) Deletes the key.
dc.listFiles(prefix) Returns matching names as a |||-delimited string.

For new plugins, dc.storage is usually easier.

Resource System

New: Plugins can now fetch text, JSON, binary blobs, and images without needing Java-side code for every resource type.

Resources are cached in memory and can be used to build richer plugins, HUDs, configuration systems, asset loaders, databases, and other tools.

Security: Downloading data is different from executing downloaded code. Resource fetching does not automatically execute downloaded JavaScript. Treat remote code as untrusted and only execute code deliberately.

Fetch text

dc.resources.fetchText(
    "rules",
    "https://example.com/rules.txt",
    function(error, text) {

        if (error) {
            dc.error(error);
            return;
        }

        dc.chat(
            "Rules loaded."
        );
    }
);

Fetch JSON

dc.resources.fetchJSON(
    "config",
    "https://example.com/config.json",
    function(error, config) {

        if (error) {
            dc.error(error);
            return;
        }

        let price =
            config.price;

        dc.chat(
            "Price: $" + price
        );
    }
);

Fetch a binary resource

dc.resources.fetchBlob(
    "asset",
    "https://example.com/asset.bin",
    function(error, blob) {

        if (error) {
            dc.error(error);
            return;
        }

        dc.log(
            "Loaded " + blob.size + " bytes."
        );
    }
);

Load an image

dc.resources.image(
    "logo",
    "https://example.com/logo.png",
    function(error, image) {

        if (error) {
            dc.error(error);
            return;
        }

        dc.log(
            "Image size: "
            + image.width
            + "x"
            + image.height
        );
    }
);

Use the cache

dc.resources.set(
    "score",
    100
);

let score =
    dc.resources.get("score");

if (dc.resources.has("score")) {
    dc.chat(
        "Score: " + score
    );
}

dc.resources.remove("score");

Import a local resource

dc.pickResource();

Listen for the import: 

dc.on(
    "resource_imported",
    function(data) {

        dc.chat(
            "Imported "
            + data.name
            + " ("
            + data.size
            + " bytes)"
        );
    }
);
Remote servers may restrict browser requests through CORS. A URL being reachable in a browser does not automatically mean JavaScript is permitted to fetch it cross-origin.

Timers

setTimeout

Run something once after a delay. 

dc.setTimeout(
    function() {
        dc.chat("Two seconds passed.");
    },
    2000
);

clearTimeout

let timeout =
    dc.setTimeout(
        function() {
            dc.chat("This may run.");
        },
        5000
    );

dc.clearTimeout(timeout);

setInterval

let interval =
    dc.setInterval(
        function() {

dc.clearInterval(interval);
Always clear intervals that your plugin no longer needs. An interval can continue running even after the relevant logic is no longer useful.

Example: TPA/payment-style automation

const PRICE = 10;

let pendingPlayer = null;

dc.createMod({

    name: "Paid TPA",

    description:
        "Requests payment before accepting TPA.",

    category: "PLAYER",

    settings: [
        dc.createSetting(
            "Slider",
            "Price",
            PRICE,
            1,
            1000,
            1
        )
    ],

    onChat: function(message) {

        let text =
            String(message);

        /*
         * Example parser.
         * Adjust this to the server's exact messages.
         */

        let tpa =
            text.match(
                /([A-Za-z0-9_]{1,16}).*teleport.*you/i
            );

        if (tpa) {

            pendingPlayer =
                tpa[1];

            let price =
                Number(
                    this.settingsCache &&
                    this.settingsCache["Price"]
                        ? this.settingsCache["Price"].value
                        : PRICE
                );

            dc.sendCommand(
                "msg "
                + pendingPlayer
                + " Pay $"
                + price
                + " first."
            );
        }
    }
});
Server automation depends on the exact text produced by the server's commands/plugins. Use chat logging while developing parsers so your regular expressions match the actual messages.

Advanced Patterns

Separate state from callbacks

const state = {
    enabled: false,
    count: 0,
    player: null
};

dc.createMod({

    name: "State Example",

    onEnable: function() {
        state.enabled = true;
    },

    onDisable: function() {
        state.enabled = false;
    },

    onUpdate: function() {

        state.count++;

        state.player =
            dc.player.name;
    }
});

Use a plugin namespace

const plugin = {

    price: 10,

    banned: {},

    pending: null,

    save: function() {

        dc.storage.set(
            "plugin_data",
            {
                price: this.price,
                banned: this.banned
            }
        );
    }
};

plugin.save();

Persistent ban list

const bans =
    dc.storage.get(
        "bans",
        {}
    );

function isBanned(name) {

    return !!bans[
        String(name).toLowerCase()
    ];
}

function ban(name) {

    bans[
        String(name).toLowerCase()
    ] = true;

    dc.storage.set(
        "bans",
        bans
    );
}

function unban(name) {

    delete bans[
        String(name).toLowerCase()
    ];

    dc.storage.set(
        "bans",
        bans
    );
}

Listen globally instead of creating a mod

dc.on(
    "chat_receive",
    function(data) {

        if (
            data.message
                .indexOf("[Server]") !== -1
        ) {

            dc.log(
                "Server message:"
                + data.message
            );
        }
    }
);

Resource + storage combination

let config =
    dc.storage.get(
        "remote_config",
        null
    );

if (!config) {

    dc.resources.fetchJSON(
        "config",
        "https://example.com/config.json",
        function(error, data) {

            if (error) {
                return;
            }

            dc.storage.set(
                "remote_config",
                data
            );
        }
    );

} else {

    dc.log(
        "Using cached config."
    );
}

Troubleshooting

"My plugin does nothing"

Start with:

dc.log("PLUGIN LOADED");

Open the browser developer console and verify that the message appears.

"My callback isn't running"

Make sure the callback is inside the object passed to dc.createMod(): 

dc.createMod({

    name: "Test",

    onUpdate: function() {

        dc.log("Tick");

    }

});

"My setting is undefined"

Check the exact setting name: 

settings["Delay"].value

The capitalization and spaces must match the setting name.

"My downloaded resource fails"

Check:

  1. The URL is correct.
  2. The remote server allows the browser request with CORS.
  3. The returned content is actually the format you expect.
  4. Your callback checks the error value.

"My plugin causes lag"

Common causes include:

  • Large loops in onUpdate.
  • Creating huge arrays or objects every tick.
  • Downloading resources repeatedly.
  • Parsing large JSON documents every frame.
  • Creating too many timers or intervals.

"My plugin was removed but behavior continues"

Check whether your plugin started a setInterval. Store its ID and call dc.clearInterval() when disabling. 

let interval = null;

dc.createMod({

    name: "Timer",

    onEnable: function() {

        interval =
            dc.setInterval(
                function() {
                    dc.chat("Ping");
                },
                1000
            );
    },

    onDisable: function() {

        if (interval !== null) {

            dc.clearInterval(
                interval
            );

            interval = null;
        }
    }

});

Plugin Security & Compatibility

Plugins execute JavaScript in the DeathClient/browser environment. Only install plugins you trust.

Remote code warning: A plugin can download arbitrary resources using browser networking APIs. Do not automatically download and execute JavaScript from an untrusted URL. Treat remote code as executable software.
API compatibility: Plugins should prefer documented dc.* functions instead of relying on undocumented internal objects such as dc._mods, dc._regQueue, or dc._internalPlayer.
